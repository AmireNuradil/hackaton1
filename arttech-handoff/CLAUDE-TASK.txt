AFTERIMAGE — IN-VIEWER SOUNDTRACK COMPARISON

Goal
Let a judge see and hear how the same saved day changes when its soundtrack
changes. The current demo proves this using two separately created memories.
Bring that comparison into the viewer as a temporary preview.

Scope
- Give the user a way to switch between the saved soundtrack and an alternate
  preview. Use the bundled soft coast.mp3 and quick city.mp3 scores to make this
  available offline. Reuse the product's existing composition logic in
  src/compose.js and its existing player in src/main.js.
- The story, photos and date stay fixed during the comparison. Recompute the
  visual timing and treatment from the soundtrack. Show a clear label and the
  current frame timing or dissolve under the existing explanation controls.
- Preview state lasts for the current viewer session. Reopening from the archive
  or reloading returns to the saved version. Download day continues to export the
  saved version. Use one archive entry for both previews.
- Keep the current visual system, keyboard operation and mobile layout. Check
  behavior for entries whose saved soundtrack is a link as well as an audio file.

Acceptance
1. Open a sample and switch to another bundled track. The pixels and timing you
   show the jury should reflect the new composition, and only the selected track should be audible.
2. Switch back and verify original playback. Close and reopen the same item,
   reload the page, and verify its original composition and archive count.
3. Download the day during preview. Its day.json and standalone player should
   still show the saved soundtrack and design.
4. Run npm test and npm run build. Check desktop and a narrow/mobile viewport.

Delivery
Start from main. Use a separate implementation branch and open a
draft PR targeting main. Return the PR link, exact commit, test
output and browser reproduction steps. Leave the merge to the team.
